========================================================================
1. WHAT THE APP IS
========================================================================
Next.js 16 / React 19 / Supabase app. You photograph textbook pages, box
each question, and build a question bank to practise from.

Phase 1 (done before session 1, tested on a phone): sign-in,
subjects/chapters/sections, photo upload with hand-drawn question boxes,
library, answers, practice, theory revision.

Phase 2 (built in session 1, reworked in session 2): auto-snipping.
Photo -> flatten -> Gemini finds where each question is -> boxes
snapped to whitespace and tiled -> Groq's Qwen reads each question's
text and options from its own crop -> you review and fix -> save with
the existing save function. Hand-drawn boxes still work on every page.

Phase 3 (built in session 3): answer keys. Key pages go through the same
capture + queue; Gemini finds short-answer tables, worked solutions and
headings (positions only); Qwen reads them; a deterministic parser turns
the text into options / numbers / text; you review the entries; saving
stores them and matches them to questions in SQL by chapter + section +
number. A matching summary per chapter handles conflicts.

3.3 Decision
------------
Split the work: Gemini only locates questions; Groq's Qwen reads each
question from its own crop (one question per call, small capped output,
fits the 1,000/min budget, can't mix questions together).

3.4 Two-stage pipeline (code)
-----------------------------
- lib/ai.ts (rewritten; still the only file that talks to AI providers,
  plain fetch, no SDKs):
  * locateQuestions(pageJpeg) -> Gemini generateContent, JSON mode,
    temperature 0. Converts box_2d to our [x0, y0, x1, y1] 0-1 bbox.
    429 -> rate_limited using Gemini's error.details[].retryDelay
    ("31s"). 503 -> rate_limited with no delay (route backs off) —
    no quick retries, since the overload lasts minutes. No content
    (e.g. RECITATION) -> treated as invalid -> one retry with the
    reason -> failed.
  * readQuestion(cropJpeg, {number, optionCount}) -> Groq chat
    completions, JSON mode, temperature 0, max_completion_tokens 700.
    finish_reason "length" -> invalid (one retry). 429 -> rate_limited
    with Groq's retry-after header.
  * Shared retry rules (withRetries): network/other 5xx -> 2 quick
    retries (0.5s, 1.5s); invalid JSON/schema -> 1 retry told the error.
  * layoutModelName() / readModelName(): env with defaults
    gemini-3.5-flash and qwen/qwen3.8-27b. Logs event "ai_call" with
    stage, model, latency, tokens.
- lib/prompts/segment.ts: LAYOUT_SYSTEM_PROMPT (positions, numbers,
  columns, types, option_count, diagram/continuation flags — explicitly
  no text), READ_SYSTEM_PROMPT (transcribe ONE question from a crop,
  ignore slivers of neighbours, keep the marks line, options without
  (a)/(b) labels), readUserPrompt(number, optionCount) (passes Gemini's
  option count as a hint).
- lib/segment/schema.ts: LayoutResponseSchema (Gemini), ReadResponseSchema
  (Groq), LocatedQuestion, QuestionFlags (+ unread, options_mismatch),
  AiQuestion / AiResult (stored, same shape as before plus option_count),
  AiProgress (partial state; text === null means not read yet).
- lib/segment/crop.ts (new): cropForReading(page, box) -> JPEG of one
  question from the full-resolution page, long edge <= 1600px.
- lib/segment/cleanup.ts: now takes LocatedQuestion[] (no text).
- app/api/pages/[pageId]/segment/route.ts (reworked):
  1. Claim as before (now also clears retry_after, selects ai_progress).
  2. If ai_progress is empty: page -> JPEG (long edge 2000) ->
     locateQuestions -> cleanup -> snapBoxes on the full page ->
     progress object with every question unread.
  3. Read each unread question in order: crop -> readQuestion.
     - Groq rate-limited: save ai_progress, status rate_limited with
       retry_after, return. The next attempt skips Gemini and resumes.
     - Read failed: keep the box, text "" and flag unread; continue.
     - mcq/msq whose option count differs from Gemini's: flag
       options_mismatch. Non-choice types drop options.
     - After 40s (READ_BUDGET_MS, under maxDuration 60): save
       ai_progress, status 'queued', return; the runner picks it up again.
  4. All read: write ai_result, ai_model "gemini-… + qwen/…", clear
     ai_progress, status needs_review, retry_count 0.
  Layout failed / crash -> status failed, ai_progress cleared.
- Review UI: two new ⚠ warnings — "couldn't read this question's text"
  and "number of options read doesn't match what's printed". Editing the
  text or options clears them. isFlagged() moved into BoxEditor.tsx and
  is shared by the review page. lib/review.ts maps the new flags.
- Settings shows both models (finds questions: Gemini; reads text: Groq).
- .env.example, README.md (setup, test checklist, "How things fit
  together") updated for Gemini, the two stages and resuming.
- .env.local: user added GEMINI_API_KEY (set, 53 chars). GEMINI_LAYOUT_MODEL
  is not set there, so the default gemini-3.5-flash is used.

3.5 Snapping changes (lib/snap.ts)
----------------------------------
- fillColumnGaps(): after overlaps are resolved, each box in a column is
  extended down to the next box's top, so nothing between two questions
  is lost (it goes to the question above).
- findNearestGap(): edges and overlap splits now go to the whitespace
  run NEAREST the model's edge (an edge already in whitespace stays in
  its own run), instead of the WIDEST run within ±3%. The old rule
  moved Gemini's correct Q4/Q5 boundary above Q4's marks line. The
  widest-run finder is still used for the column gutter.
- Known limit: on a tilted, un-flattened photo, a marks line that
  nearly touches the next question's first line has no clean gap, so
  the boundary cuts through it (seen on Q1/Q2 and Q2/Q3 of the test
  page). Flatten fixes the tilt; the save route's 2% crop padding covers
  the half line.

4.2 Database: supabase/migrations/20261006000000_phase3_answer_keys.sql
-----------------------------------------------------------------------
- Enums answer_entry_kind (short | worked) and answer_entry_status
  (unmatched | matched | conflict | ignored | kept_mine).
- pages gets unique (id, chapter_id, user_id) so entries can prove their
  chapter is their page's.
- Table answer_key_entries: user_id default auth.uid(), RLS owner
  policy, composite FKs (page+chapter+user cascade; section set null on
  delete; question set null on delete), number_normalized generated,

  answer_text, parse_flags), image_path (worked only), bbox real[4],
  status, question_id, conflict_reason. No "matched implies question"
  check: deleting a question nulls question_id on matched entries until
  the app re-matches (it does, right after).
- match_answer_key_entries(chapter): pg_advisory_xact_lock(
  hashtextextended(chapter::text, 0)); resets everything except
  ignored / kept_mine; deletes stale key answers (source_page_id = a key
  page with no non-ignored entry for that question any more); flags
  same-kind duplicates on one page; per question combines the short
  entry (options/number/text, interpreted by question type via
  answer_key_interpret) and the worked entry (image + text); inserts
  answers with on conflict (question_id) do nothing, then reconciles an
  existing answer: its own page's answer is updated/deleted to match
  the key; a hand answer (source_page_id null) or another page's answer
  is never overwritten — only empty fields are filled (e.g. the
  solution image); a different option/number is a conflict
  (differs_from_your_answer / differs_from_key_answer). Text never
  conflicts. Other reasons: multiple_options_on_mcq, option_on_numerical,
  number_on_mcq, option_on_theory, unreadable_answer, key_no_answer,
  duplicate_number, key_pages_disagree (answer left as is until resolved).
- save_answer_key_page(page, entries): row lock, refuses a saved page,
  inserts entries, matches, marks saved — one transaction.
- apply_answer_key_entry(entry): "Use key answer" — deletes the current
  answer and re-matches.
- delete_answer_key_page(page): deletes answers the page wrote that
  weren't edited since; keeps hand-edited ones (image included); clears
  the borrowed image from other key answers (deleting them if nothing
  else is left); deletes the page (entries cascade); re-matches; returns

including this machine's @rolldown/binding-win32-x64-msvc, which
vitest needs (and vite's lightningcss binary). After one install,
vitest wouldn't start ("Cannot find native binding"). `npm ci` couldn't
help because the running dev server locks a native file.
What was done: package-lock.json and package.json restored from git,
then ONLY the @electric-sql/pglite entry added to both by a small
script (diff: 9 lines); the three missing packages unpacked from their
published tarballs into node_modules. `npm ls` now shows only two
harmless "extraneous" leftovers.
Before running `npm install` here again: stop the dev server, and check
`git diff --stat package-lock.json` afterwards; a few-hundred-line
deletion means it happened again (fix: delete node_modules and run
`npm ci`).
