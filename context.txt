========================================================================
1. WHAT THE APP IS
========================================================================
Next.js 16 / React 19 / Supabase app. You photograph textbook pages, box
each question, and build a question bank to practise from.

Phase 1 (done before session 1, tested on a phone): sign-in,
subjects/chapters/sections, photo upload with hand-drawn question boxes,
library, answers, practice, theory revision.

Phase 2 (built in session 1, reworked in session 2): auto-snipping.
Photo -> flatten -> Gemini finds where each question is -> boxes
snapped to whitespace and tiled -> Groq's Qwen reads each question's
text and options from its own crop -> you review and fix -> save with
the existing save function. Hand-drawn boxes still work on every page.
Answer-key pages keep the Phase 1 manual flow.

  the page, sorts by column then top edge, flags duplicate numbers and
  sequence gaps (uses lib/number.ts).
- lib/snap.ts: sharp-based snapping — column gutter detection, top and
  bottom edges moved into whitespace near the model's edge (±3% of

- app/api/pages/[pageId]/segment/route.ts: processes one page.
  Checks the caller with the normal session first, then uses the
  service-role client with every query filtered by that user_id.
  Claims the page with one conditional UPDATE (queued, or rate_limited
  past retry_after, or stuck in processing > 3 min). Backoff when the
  provider gives no delay: 10s doubling per attempt, max 5 min
  (retry_count). Final updates only apply while the page is still
  'processing', so a late AI result can't overwrite a page you saved by
  hand. (Reworked for the two stages in session 2.)
- app/api/pages/[pageId]/save/route.ts: accepts text and options per
  question; crops (+2% padding) from the flattened copy when there is
  one (that is the image the boxes were drawn on); uses lib/log.ts.
- app/api/groq/test/route.ts: signed-in only; lists Groq models to

3.1 Setup problems found running the app for real
-------------------------------------------------
- "supabaseKey is required": SUPABASE_SERVICE_ROLE_KEY was empty in
  .env.local. User filled it in. lib/supabase/service.ts now throws a
  clear "SUPABASE_SERVICE_ROLE_KEY is not set … restart the dev server"
  instead of the Supabase library's message.
- Hot retry loop: any failure before the page was claimed left it
  'queued', and lib/queue/runner.ts retried every 250ms forever (20+
  requests in a few seconds). The runner now backs off on a non-OK
  response or network error: 2s, 4s, 8s … up to 60s. A 409 (someone
  else claimed the page) counts as OK.
- "column pages.retry_count does not exist": the Phase 2 migration had
  never been run. Applied with `supabase db push` (CLI is linked).
- "violates check constraint pages_check1": that constraint is
  (status = 'rate_limited') = (retry_after is not null). The claim set
  status 'processing' but left retry_after set, so every page that had
  been rate-limited once failed on retry. The claim now also sets
  retry_after = null.
- Same bug on manual Save: save_page_questions() set status 'saved'
  without clearing retry_after, so saving a rate-limited page by hand
  failed. Fixed in migration 20261005000100 (3.6).

3.2 Accuracy problem: what was tested (scripts in the session
     scratchpad, not the repo; test page = a 2-column GATE "Array" page)
----------------------------------------------------------------------
Symptom: boxes in the wrong place, Q4 missing its options (b)–(d),
Q3's last lines and options outside every box, Q1's text mixed with Q2's.
Findings, all on the same page:
- Groq qwen/qwen3.8-27b, bbox 0-1 (old prompt): coordinates are round
  guesses (0.05, 0.15, 0.42, 0.78…). Text also mixed between questions.
- Same model, 0-1000 integer coordinates: slightly better, still
  guesses (100, 60, 480, 150…); still clipped Q3's (d) and Q5's end.
- Same model, grounding-only prompt in Qwen's native bbox_2d format:
  invented output (8 "question numbers" exactly 122 units apart).
  Conclusion: this model cannot localise; no prompt fixes it.
- Groq free tier limit: 1,000 OUTPUT tokens per minute for this model.
  One full-page reply was ~1,500 tokens. Groq rejects a request whose
  EXPECTED output is too large ("Request too large", HTTP 429); when
  max_completion_tokens is not set it seems to estimate from recent
  usage. Setting max_completion_tokens explicitly avoids that.
- Free-API options looked at: Gemini (AI Studio free tier, chosen),
  OCR.space (word boxes only), OpenRouter free models (50 req/day),
  Google Cloud Vision / Azure (need a card). Local Tesseract.js was the
  fallback plan if Gemini's boxes had been bad.
- Gemini models available to this key: gemini-2.5-flash is NOT
  available to new users; 3.5/3.7/3.8-flash and flash-latest exist.
  The free tier returned 503 "high demand" on most models for 5+
  minutes at a time.
- Gemini asked for full text: finishReason RECITATION (refuses to copy
  copyrighted book text). So Gemini can never be used for the text.
- Gemini 3.5 Flash, layout only (box_2d [ymin, xmin, ymax, xmax]
  0-1000, no text): all 5 boxes essentially right, including Q3/Q4/Q5
  with all options and the marks line; numbers, columns, types and
  option counts (4,0,4,4,0) all right. ~400 output tokens, ~16s.

3.3 Decision
------------
Split the work: Gemini only locates questions; Groq's Qwen reads each
question from its own crop (one question per call, small capped output,
fits the 1,000/min budget, can't mix questions together).

3.4 Two-stage pipeline (code)
-----------------------------
- lib/ai.ts (rewritten; still the only file that talks to AI providers,
  plain fetch, no SDKs):
  * locateQuestions(pageJpeg) -> Gemini generateContent, JSON mode,
    temperature 0. Converts box_2d to our [x0, y0, x1, y1] 0-1 bbox.
    429 -> rate_limited using Gemini's error.details[].retryDelay
    ("31s"). 503 -> rate_limited with no delay (route backs off) —
    no quick retries, since the overload lasts minutes. No content
    (e.g. RECITATION) -> treated as invalid -> one retry with the
    reason -> failed.
  * readQuestion(cropJpeg, {number, optionCount}) -> Groq chat
    completions, JSON mode, temperature 0, max_completion_tokens 700.
    finish_reason "length" -> invalid (one retry). 429 -> rate_limited
    with Groq's retry-after header.
  * Shared retry rules (withRetries): network/other 5xx -> 2 quick
    retries (0.5s, 1.5s); invalid JSON/schema -> 1 retry told the error.
  * layoutModelName() / readModelName(): env with defaults
    gemini-3.5-flash and qwen/qwen3.8-27b. Logs event "ai_call" with
    stage, model, latency, tokens.
- lib/prompts/segment.ts: LAYOUT_SYSTEM_PROMPT (positions, numbers,
  columns, types, option_count, diagram/continuation flags — explicitly
  no text), READ_SYSTEM_PROMPT (transcribe ONE question from a crop,
  ignore slivers of neighbours, keep the marks line, options without
  (a)/(b) labels), readUserPrompt(number, optionCount) (passes Gemini's
  option count as a hint).
- lib/segment/schema.ts: LayoutResponseSchema (Gemini), ReadResponseSchema
  (Groq), LocatedQuestion, QuestionFlags (+ unread, options_mismatch),
  AiQuestion / AiResult (stored, same shape as before plus option_count),
  AiProgress (partial state; text === null means not read yet).
- lib/segment/crop.ts (new): cropForReading(page, box) -> JPEG of one
  question from the full-resolution page, long edge <= 1600px.
- lib/segment/cleanup.ts: now takes LocatedQuestion[] (no text).
- app/api/pages/[pageId]/segment/route.ts (reworked):
  1. Claim as before (now also clears retry_after, selects ai_progress).
  2. If ai_progress is empty: page -> JPEG (long edge 2000) ->
     locateQuestions -> cleanup -> snapBoxes on the full page ->
     progress object with every question unread.
  3. Read each unread question in order: crop -> readQuestion.
     - Groq rate-limited: save ai_progress, status rate_limited with
       retry_after, return. The next attempt skips Gemini and resumes.
     - Read failed: keep the box, text "" and flag unread; continue.
     - mcq/msq whose option count differs from Gemini's: flag
       options_mismatch. Non-choice types drop options.
     - After 40s (READ_BUDGET_MS, under maxDuration 60): save
       ai_progress, status 'queued', return; the runner picks it up again.
  4. All read: write ai_result, ai_model "gemini-… + qwen/…", clear
     ai_progress, status needs_review, retry_count 0.
  Layout failed / crash -> status failed, ai_progress cleared.
- Review UI: two new ⚠ warnings — "couldn't read this question's text"
  and "number of options read doesn't match what's printed". Editing the
  text or options clears them. isFlagged() moved into BoxEditor.tsx and
  is shared by the review page. lib/review.ts maps the new flags.
- Settings shows both models (finds questions: Gemini; reads text: Groq).
- .env.example, README.md (setup, test checklist, "How things fit
  together") updated for Gemini, the two stages and resuming.
- .env.local: user added GEMINI_API_KEY (set, 53 chars). GEMINI_LAYOUT_MODEL
  is not set there, so the default gemini-3.5-flash is used.

3.5 Snapping changes (lib/snap.ts)
----------------------------------
- fillColumnGaps(): after overlaps are resolved, each box in a column is
  extended down to the next box's top, so nothing between two questions
  is lost (it goes to the question above).
- findNearestGap(): edges and overlap splits now go to the whitespace
  run NEAREST the model's edge (an edge already in whitespace stays in
  its own run), instead of the WIDEST run within ±3%. The old rule
  moved Gemini's correct Q4/Q5 boundary above Q4's marks line. The
  widest-run finder is still used for the column gutter.
- Known limit: on a tilted, un-flattened photo, a marks line that
  nearly touches the next question's first line has no clean gap, so
  the boundary cuts through it (seen on Q1/Q2 and Q2/Q3 of the test
  page). Flatten fixes the tilt; the save route's 2% crop padding covers
  the half line.

6. KNOWN LIMITS / POSSIBLE NEXT STEPS
========================================================================
- Throughput is set by Groq's free-tier 1,000 output tokens/min
  (~1 page every 1.5–2 min). Groq's Dev tier removes it.
- Gemini's free tier is often overloaded (503); pages just wait and
  retry. Free-tier input may be used by Google to improve its products.
- Queue runner idles 20s when nothing is claimable, so each rate-limit
  wait can stretch by up to 20s past retry_after. Could wake the runner
  at the earliest retry_after instead (small change in runner.ts).
- No "Test Gemini connection" button in Settings yet.
- Pages read by the old one-call pipeline keep their old boxes until
  re-queued.
- Qwen sometimes leaves out the marks line when it sits below the
  options (seen on Q4 when the box excluded it).
